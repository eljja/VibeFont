## 1. 토크나이징: 포인트 양자화 vs 베지어

### 판정: **Phase 1~2는 포인트 기반으로 시작. 베지어는 보류.**

**베지어를 미루는 이유**
1. **목표와 충돌함.** VibeFont의 핵심은 미세한 떨림과 불규칙성인데, 베지어 피팅은 정확히 그 고주파 성분을 매끄럽게 지워버림.
2. 세그먼트 하나에 연속값 6~8개(제어점 + 시간)가 들어가서 토큰 하나의 정보 밀도가 너무 높아지고, 이산 분류로 다루기 어려움.
3. 피팅 오차 허용치, 세그먼트 분할점 같은 하이퍼파라미터가 데이터 자체에 섞여 들어감.

**포인트 방식에서 v1.0의 문제와 수정안**

- **(a) 시퀀스 길이 4배 증가 문제.** v1.0처럼 Δx, Δy, p, s를 각각 토큰으로 두면 시퀀스가 4배로 늘어남.  
  → **1 포인트 = 1 포지션** 구조로 바꿈. 입력은 각 채널 임베딩의 합으로 넣고, 출력은 **자기회귀 분해 헤드**로 처리:
  $$P(\Delta x,\Delta y,s\mid h)=P(s\mid h)\,P(\Delta x\mid h,s)\,P(\Delta y\mid h,s,\Delta x)$$
  Δx와 Δy를 서로 독립인 헤드로 두면 대각선 획에서 상관관계를 잃으므로, Δy를 Δx에 조건부로 둠.
- **(b) 양자화 누적 오차(drift).** 델타를 독립적으로 양자화하면 오차가 계속 쌓여서 긴 줄 끝에서는 궤적이 틀어짐.  
  → **오차 피드백 양자화**를 사용: 원래 좌표가 아니라 *복원된 이전 좌표* 기준으로 델타를 계산함.
  $$\hat{\mathbf{x}}_i=\hat{\mathbf{x}}_{i-1}+Q(\mathbf{x}_i-\hat{\mathbf{x}}_{i-1})$$
- **(c) 균등 격자의 해상도 낭비.** 델타 분포는 0 근처에 몰려 있음.  
  → **μ-law 또는 분위수(quantile) 기반 비균등 bin** 사용. bin 개수는 축마다 128~256개면 충분함("8-bit or 10-bit, ±512"는 서로 맞지 않는 표기이므로 삭제).
- **(d) 리샘플링이 속도 정보를 지움 (셰이더와 직결되는 문제).** 호 길이(arc-length) 기준으로 균등 리샘플링하면 **속도가 사라져서** 셰이더가 잉크 고임(pooling)을 계산할 수 없음.  
  → **시간 기준 균등 리샘플링**(예: 원본 타임스탬프로 60~100Hz 재샘플)을 하거나, RDP 단순화를 쓰려면 **Δt 채널을 추가**함.

### MDN vs 이산 분류
| | MDN (Graves 2013) | 이산 분류 (분해 헤드) |
|---|---|---|
| 장점 | 연속 출력, 파라미터 적음, 검증된 기준선 | 학습 안정적, 다봉(multimodal) 분포 표현이 자유로움, temperature 제어가 직관적 |
| 단점 | 분산 붕괴/NaN 불안정성, 혼합 개수 튜닝 필요 | 양자화 오차, 출력층 크기 |

→ **권장:** 메인은 이산 분류. 단, 소형 MDN 기준선(Graves 재현)을 **같은 데이터와 평가 지표로 1회 비교**함. 기준선 없이는 "트랜스포머가 더 낫다"는 주장을 검증할 수 없음.

## 2. 텍스트-궤적 정렬 (Monotonic Attention)

### 판정: **일반 Cross-Attention만 쓰는 것은 위험. 단조 정렬 장치가 필요함.**

TTS(Tacotron 계열)에서도 같은 문제(글자 건너뛰기, 반복, 생성이 끝나지 않음)가 잘 알려져 있음. 손글씨는 출력 길이 대비 입력 길이 비율이 TTS보다 더 크므로 위험도 더 높음.

**권장안 (우선순위 순)**

1. **강제 정렬 + 하드 조건부 (최우선 권장)**
   - 소형 **온라인 HTR(CTC) 인식기**를 먼저 학습하고 → CTC 강제 정렬로 각 포인트에 "현재 글자 인덱스"를 부여함.
   - 디코더 입력에 *현재 글자 + 다음 글자 임베딩*을 직접 넣고, 글자 전환은 `ADVANCE` 플래그(기존 `END_OF_CHAR`를 대체)로 모델이 예측하게 함.
   - 정렬 드리프트가 구조적으로 불가능해짐. 같은 HTR 모델을 **평가 지표(CER)로 재사용**할 수 있으므로 일석이조.
2. **Graves식 단조 가우시안 윈도우 (대안 / 기준선)**
   $$\kappa_t=\kappa_{t-1}+\exp(\hat\kappa_t),\quad \phi(t,u)=\sum_k \alpha_t^k \exp\!\big(-\beta_t^k(\kappa_t^k-u)^2\big)$$
   - $\kappa$가 단조 증가하도록 강제되므로 역행하지 않음. 학습 초기에 불안정할 수 있음.
3. **로컬 윈도우 마스크**는 위 방식들의 보조 수단으로만 사용함(단독으로 쓰면 윈도우 위치를 결정하는 문제가 그대로 남음).

## 3. 모델 규모 재산정

### v1.0 수치 검산
12층, d=512, FFN 2048, cross-attention 포함 디코더의 층당 파라미터:
$4d^2$ (self) $+ 4d^2$ (cross) $+ 2\cdot d\cdot 4d$ (FFN) $= 16d^2 \approx 4.2$M → 12층이면 **약 50M**. v1.0의 "~120M"은 계산 오류임.

### 데이터 대비 적정 규모
- IAM-OnDB 약 13k 줄 × 줄당 약 700~1,000 포인트 ≈ **포인트 토큰 약 1,000만 개**.
- 이 정도 데이터에서 50M 이상 모델은 과적합 가능성이 높음. Graves 2013은 **약 3.6M 파라미터**로 좋은 결과를 냈음.

| 트랙 | v1.0 | **수정안** | 근거 |
|---|---|---|---|
| Track A | 120M | **5~25M** (데이터가 늘면 확장) | 데이터 규모, WebGPU 지연 시간 |
| Track B 디코더 | 800M | **50~300M** | 스타일 정보는 인코더가 담당하므로 디코더가 클 필요가 없음 |
| Track B 인코더 | DINOv2 | 동결 백본 약 20~90M + Resampler | §4 |

> [!IMPORTANT]
> "0.5~1.5B"는 앞선 대화에서 감으로 제시된 수치이며 근거가 없음. 규모는 **데이터를 확보한 뒤 스케일링 실험(5M→25M→100M)으로 결정**해야 함.

## 4. Track B: 스타일 인코더

### DINOv2 vs SigLIP
- **SigLIP/CLIP:** 의미(semantic) 정렬로 학습되어서 "손글씨 이미지"라는 개념은 잘 잡지만, 기울기·곡률·자간 같은 기하학적 차이는 오히려 지워버리는 경향이 있음. **비권장.**
- **DINOv2:** 자기지도 학습이라 저수준 구조를 더 잘 보존하므로 둘 중에서는 나음. 다만 자연 이미지로 학습되었고, 얇은 획과 흰 배경 위주인 손글씨는 분포가 다름.
- **선행연구 관행:** HWT(Bhunia 2021), VATr, SDT(Dai 2023) 등은 **writer-ID 분류/대조 학습으로 처음부터 학습한 ResNet/CNN 스타일 인코더**를 씀.

→ **권장:** ① writer-ID 대조 학습으로 처음부터 학습한 소형 CNN/ViT, ② DINOv2-small 파인튜닝. **이 두 가지를 writer 검색 정확도로 비교한 뒤 결정**함.

### Perceiver Resampler
- K=32 정도면 병목은 크지 않음. 실제 위험은 **내용 누출(content leakage)**: 참조 이미지의 *글자 내용*이 스타일 토큰에 섞여 들어가서, 생성 결과에 참조 단어가 복사되는 현상.
  → 대조 학습에서 **같은 작성자 + 다른 텍스트**를 positive로 쓰는 것(v1.0에 이미 있음)에 더해, 참조 이미지를 **패치 셔플/단어 단위 크롭**으로 증강해서 내용 정보를 깨뜨림.

### 학습 데이터 쌍 문제 (v1.0에 누락)
Track B는 **입력이 이미지(오프라인), 출력이 궤적(온라인)**임. 학습하려면 같은 작성자의 (이미지, 궤적) 쌍이 필요함.
- IAM-OnDB 궤적을 **렌더링해서 이미지를 합성**하면 쌍을 확보할 수 있음. 단, 실제 사진(종이, 조명, 실제 펜)과의 **도메인 격차**가 생김.
- → 렌더링할 때 **이번 프로젝트의 잉크 셰이더 + 종이 텍스처 + 사진 열화**를 적용하면 셰이더 개발이 데이터 증강에도 쓰이는 시너지가 생김.

## 5. 폰트 스켈레톤화에 대한 근본적 이의

### 판정: **영문에는 비권장. 한글에는 다른 방식을 제안함.**

1. **목적과 모순됨:** 폰트에서 추출한 궤적은 바로 VibeFont가 벗어나려는 "정적 글리프"임. 속도·필압 같은 동역학 정보도 없음(시간 정보를 임의로 만들어야 함). 이 데이터를 대량으로 섞으면 모델이 **기계적인 필체**를 배울 위험이 있음.
2. **교차점 모호성:** Zhang-Suen 같은 래스터 세선화는 교차점에서 가지(spur)와 왜곡이 생김. 꼭 써야 한다면 벡터 외곽선 → Constrained Delaunay → **Chordal Axis Transform** → 가지 제거 → 교차점에서 **접선 연속성(good continuation)**으로 획을 짝짓기 → 표준 획순 규칙 적용 순서로 처리함. 그래도 정확도에 한계가 있음.

### 한글 대안 (권장)
한글은 **자모 조합 구조**라는 큰 장점이 있음.
- 11,172자 전체가 아니라 **위치별 자모 변형(약 수십~수백 종) × 조합 틀**만 실제 온라인 데이터로 수집하면 됨.
- **자체 수집 도구**(태블릿/스타일러스용 웹앱, Pointer Events API로 x, y, t, pressure, tilt 기록)를 Phase 1 산출물에 추가함. 이렇게 하면 **IAM-OnDB에 없는 필압과 기울기(tilt) 데이터도 확보**됨.
- 기존 공개 데이터는 **검증 필요**(AI Hub 등에 온라인 궤적이 있는지 확인).

## 6. 평가 체계 (v1.0에 완전히 누락 → 신설)

| 지표 | 측정 대상 | 방법 |
|---|---|---|
| **가독성** | 철자 정확도 | 생성 궤적을 온라인 HTR에 넣어 **CER/WER** 측정 (§2의 HTR 재사용) |
| **스타일 충실도** (Track B) | 참조 작성자와의 일치 | writer-ID 분류기 정확도 / 스타일 임베딩 코사인 유사도 |
| **인스턴스 다양성** | "같은 단어도 매번 다르게" | 같은 입력으로 N회 생성한 결과 간 **DTW 거리 분포**. 0이면 실패, 너무 크면 가독성 저하 |
| **자연스러움** | 사람다움 | 궤적 특징 기반 FID 유사 지표 + 소규모 사람 블라인드 테스트 |
| **성능** | 실시간성 | WebGPU에서 포인트/초 (목표: 실시간 필기 속도 약 100~200pt/s의 수 배) |

> [!TIP]
> 다양성과 가독성은 trade-off 관계임. Graves의 **sampling bias**(분포를 날카롭게 만드는 파라미터)처럼 사용자가 "정갈함 ↔ 자유로움"을 조절하는 슬라이더를 제공하는 것이 제품 측면에서도 좋음. 단, 변동은 **같은 작성자 안에서의 변동**이어야 함 → 스타일 벡터는 고정하고 샘플링 노이즈만 바꿈.

## 7. 셰이더 인터페이스

### 모델이 출력할 최소 세트
**(x, y, t, pen_state)** 만 출력. 나머지는 렌더러에서 유도함.
- 속도 $v_i=\|\mathbf{x}_i-\mathbf{x}_{i-1}\|/\Delta t_i$, 가속도, 곡률은 **해석적으로 계산** 가능하므로 모델이 예측할 필요 없음.
- 필압: 실측 데이터가 있으면 선택 채널, 없으면 $\tilde p = \sigma(a - b\,v)$ 같은 **속도 기반 유사 필압**.
- 펜 각도/기울기: 데이터셋에 없음 → **셰이더 파라미터**(사용자 설정)로 둠.

### 펜별 물리 근사식
- **넓은 펜촉(캘리그래피):** 획 폭 $w=W\,|\sin(\theta_{\text{stroke}}-\theta_{\text{nib}})|+w_{\min}$ — 펜촉 각도는 고정하고 획의 방향에 따라 굵기가 자연스럽게 변함.
- **만년필:** 잉크 침착량 $\propto$ 체류 시간 $\propto 1/v$ → 느린 곳과 획 끝에 고임. 번짐(feathering)은 종이 섬유 노이즈 텍스처 기반 비등방성 블러를 후처리 패스로 처리함.
- **볼펜:** 밀도 $\propto f(p)\cdot g(v)$ + 호 길이 방향 1D 노이즈로 스킵을 표현. 획 시작점에 잉크 뭉침(goop) 확률을 둠.
- **구현:** 폴리라인 → 정점별 속성(v, p, 호 길이)을 가진 리본 메쉬 → 프래그먼트 셰이더 → 종이 합성 패스. WebGL2로 먼저 만들고 WebGPU는 이후에 적용.

## 8. 선행연구 포지셔닝 (v1.0에 누락)

| 연구 | 관련성 |
|---|---|
| **Graves 2013** (LSTM + MDN + 단조 윈도우) | Track A의 직접적인 원형 |
| **calligrapher.ai** (Graves 모델의 브라우저 구현) | **Track A와 거의 같은 데모가 이미 존재함** |
| **DeepWriting** (Aksan et al. 2018) | 스타일/내용 분리, 온라인 필기 편집 |
| **Decoupled Style Descriptors** (Kotani et al. ECCV 2020) | 몇 개 샘플로 온라인 필기 스타일 모사 |
| **SDT** (Dai et al. CVPR 2023) | **오프라인 스타일 참조 이미지 → 온라인 궤적 생성**. Track B의 가장 가까운 선행연구이자 기준선 |
| HWT / VATr / DiffusionPen | 오프라인(이미지) 손글씨 생성, 스타일 인코더 설계 참고용 |

> [!WARNING]
> Track A의 *모델 자체*에는 신규성이 거의 없음. VibeFont의 차별점은 **① 한글 지원, ② 물리 잉크 셰이더, ③ 실시간 웹/온디바이스 제품화, ④ 가독성-다양성 제어 UX**에 두어야 함.

또한 "Diffusion보다 AR이 우월하다"는 v1.0의 단정은 과장임. AR을 선택하는 근거는 **실시간 스트리밍, 경량화, 정렬 제어의 용이성**으로 한정해서 서술해야 함.
